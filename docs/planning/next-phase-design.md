기준: 2026-10-21 KST. 상태: **설계 확정**. 2026-10-20에 초안을 쓰고, 2026-10-21에 미결정 질문 10개의 답을 받아 반영했다([확정 결정 기록](#확정-결정-기록-2026-10-21)). 다음 단계는 구현 계획 작성이다. "사용자 결정"은 사용자가 대화에서 확정한 내용이고, "(제안)"은 설계자가 정한 기본값으로 구현 중에 바꿀 수 있다. 구현이 끝난 결정은 각 기능 문서와 [요구사항 SOT](requirements.md)로 옮기고 이 문서에서는 지운다.

## 다른 컴퓨터에서 이어서 작업하기

Git에 없는 파일이 있어서 저장소를 clone하는 것만으로는 이어서 작업할 수 없다. 아래 파일은 비밀번호 관리자나 암호화된 저장소처럼 안전한 경로로 직접 옮긴다. Git, 채팅, 메신저로 보내지 않는다.

| 파일                                                      | 용도                                                               |
| --------------------------------------------------------- | ------------------------------------------------------------------ |
| `.local/deployment.json`                                  | 개인 GCP 계정·프로젝트 지정. 모든 운영 스크립트가 읽는다           |
| `.local/deployment-account.md`                            | 사용 금지 회사 계정·프로젝트 명시. 없으면 운영 스크립트가 중단한다 |
| `.local/owner-access.json`                                | 최초 관리자 로그인 정보와 소유자 ID                                |
| `infra/gcp/terraform.tfstate`, `terraform.tfstate.backup` | 실제 인프라 상태. 없으면 Terraform이 리소스를 새로 만들려 한다     |
| `infra/gcp/terraform.tfvars`                              | 프로젝트·저장소 변수(비밀 아님, gitignore 대상)                    |

새 컴퓨터에서 할 일:

1. `gh auth login -h github.com` 후 저장소를 clone하고 `npm ci`를 실행한다.
2. `gcloud auth login <.local/deployment.json의 account>`로 사용자가 지정한 개인 계정에 로그인한다. 기본 프로젝트 설정에 의존하지 않고, 모든 명령에 계정·프로젝트를 명시한다([AGENTS.md](../../AGENTS.md)의 Deployment identity boundary).
3. 위 파일을 같은 경로에 둔 뒤 `node scripts/gcp.mjs doctor`와 `node scripts/connect-toss.mjs`(읽기 전용 사전 확인)로 접근을 확인한다.
4. `cd infra/gcp && terraform init` 후 `node scripts/gcp.mjs plan` 결과가 "No changes"인지 확인한다. Terraform 버전은 state와 같은 1.14.3을 쓴다.

Windows 참고(2026-10-21 확인):

- Terraform은 `winget install --id Hashicorp.Terraform --version 1.14.3 --exact`로 설치한다. 처음 `terraform init`을 하면 `.terraform.lock.hcl`에 Windows용 provider 해시가 한 줄 추가되는데, 정상이므로 커밋한다.
- `scripts/gcp.mjs`와 `scripts/connect-toss.mjs`는 Windows에서 동작하지 않는다. `execFileSync('gcloud')`가 셸 없이 `gcloud.cmd`를 실행하지 못해 `spawnSync gcloud ENOENT`로 끝난다([운영 과제](#남은-작업-순서) 참고). 고치기 전에는 macOS/Linux/WSL에서 돌리거나, 스크립트가 하는 읽기 전용 확인을 gcloud로 직접 실행한다.
- Git 전역 설정이 `core.autocrlf=true`이면 체크아웃 파일이 CRLF가 되어 `npm run format:check`(따라서 `npm run check`)가 실패한다. 저장소에 `.gitattributes`(`* text=auto eol=lf`)를 추가하는 것이 근본 해결이다([운영 과제](#남은-작업-순서)). 그 전에는 저장소 로컬 설정 `git config core.autocrlf input` 후 다시 체크아웃한다.
- 같은 이유로 `infra/gcp/firestore.rules`가 CRLF이면 `plan`이 Firestore 규칙(`google_firebaserules_ruleset`, `_release`)을 교체하려 한다. 내용은 같고 줄바꿈만 다르다. 이 상태로 `apply`하지 않는다. 파일을 LF로 바꾼 뒤 `plan`이 "No changes"인지 다시 확인한다(2026-10-21 확인: LF로 바꾼 뒤 No changes).
- gcloud 토큰이 만료되면 `invalid_grant`가 난다. `gcloud auth login <지정 개인 계정>`으로 다시 로그인한다.

## 배경과 목적

토스 실계좌 연결이 2026-10-20에 끝났고 사용자가 실제 보유 종목과 금액이 보이는 것을 확인했다. 다음 목표는 세 가지다.

1. 화면의 데모 데이터를 없애고 실제 API 데이터로만 계산한다.
2. 차트 화면을 "종목 분석" 탭으로 확장해 지표, 이벤트, 재무, 수급을 한곳에서 본다.
3. 차트·재무·뉴스·수급을 종합하는 매매 알고리즘을 만들고, 시뮬레이션과 모의 운용으로 검증한 뒤 실제 자동 매매에 쓴다.

실패로 볼 상황(사용자가 가장 꺼리는 것): 과도한 매매로 수수료·환전 비용이 수익을 잠식하는 것.

## 1. 데모 제거 (사용자 결정)

현재 데모 데이터는 화면 코드에만 있다: `src/lib/market.ts`의 고정 시세(`demoPrices`)와 2026년 10월 예시 일정(`events`). 각 화면이 데모 상태로 시작한다.

- 캘린더·차트·AI 인사이트의 "합성 데모 / 실제 데이터" 전환 버튼과 데모 데이터를 없앤다.
- 내 자산의 예시 보유 종목과 "DEMO" 표시를 없앤다.
- 상단 "예시 시세" 띠(`App.tsx`)를 토스 `/api/v1/market-indicators/prices` 실제 값으로 바꾼다.
- 로그인하지 않은 "둘러보기 모드"를 없애고 로그인 화면만 보여 준다.
- 사용 범위(사용자 결정 2026-10-21): 이번 단계의 실데이터 화면, 종목 분석, 캘린더 갱신 결과, 알고리즘, 주문은 **소유자 전용**이다. 새 API는 서버에서 소유자인지 검사한다(현재 토스 연결과 같은 `TOSS_OWNER_USER_ID` 기준). 다른 등록 계정은 로그인하면 "소유자 계정 전용 기능" 안내만 본다. 계정별 토스 연결은 범위 밖이며, 필요해지면 별도 작업으로 한다.
- 새 전략의 입력 초기값(`lib/strategy.ts`)은 데모가 아니므로 유지한다.
- 데이터를 못 받으면 데모로 대체하지 않고 원인을 구분해 보여 준다: 토스 미연결, 해당 종목 데이터 없음, 일시 오류(다시 시도).
- E2E 테스트(`tests/app.spec.ts` 등)가 데모 화면을 검사하므로, 가짜 API 응답 주입(`page.route`)과 `tests/fixtures`로 바꾼다. 가짜 데이터는 테스트 코드에만 둔다.

## 2. 종목 분석 탭 (사용자 결정)

탭 이름을 "차트 분석"에서 "종목 분석"으로 바꾼다. 배치는 시안 A로 정했다: 위에서부터 종목 검색·요약, 지표 선택, 이벤트 필터, 넓은 차트, 차트 아래 분석 탭.

**종목 요약**: 현재가, 등락률, 시가총액, PER, PBR, 매수 유의사항 배지(투자경고·거래정지·상하한가 근접; 토스 `/stocks/{symbol}/warnings`, `/price-limits`).

**지표**

- 지표마다 ⓘ 호버 설명: 무엇을 계산하는지와 보통 어떻게 해석하는지 두세 문장.
- 기존 SMA·EMA·볼린저 밴드·RSI·MACD에 추가(제안): 일목균형표, VWAP, 스토캐스틱, ATR, OBV, 파라볼릭 SAR, ADX, CCI, 켈트너 채널, 피보나치 되돌림.
- 시장 지표 겹쳐 보기: 코스피, S&P 500, 원/달러 등을 기준 100으로 정규화(토스 `/market-indicators/{symbol}/candles`).
- 내 매매 표시: 평균 매수가 가로선, 알고리즘 체결 지점 ▲▼ 마커.

**이벤트 수직선**

- 해당 날짜에 점선과 이름표를 그린다. 필터: 중요도(최상·높음·보통), 종류(금리 결정·실적 발표·경제 지표·공시), 시장(미국·국내).
- 출처: 금리 결정은 기존 연준·한국은행 수집, 경제 지표는 FRED·ECOS, 국내 실적·공시는 DART, 미국 실적은 SEC 공시. 미국 실적 발표 **예정일**은 무료 공식 출처가 없어 발표 후 날짜만 그린다.

**분석 탭** (차트 아래)

- 가치 지표: PER, PBR, ROE, EPS. 재무 데이터와 토스 현재가로 직접 계산하고 출처·계산 시점을 표시한다. 같은 업종 비교(토스 `/sectors`)로 업종 평균과 나란히 보여 준다.
- 연간·분기 재무: 매출, 영업이익, 순이익, 자산, 부채, 자본. 국내 DART, 미국 SEC EDGAR.
- 투자자 동향(외국인·기관·개인 순매수), 공매도·신용·프로그램매매: 토스 API가 국내 종목만 제공한다. 미국 종목에서는 제공하지 않는다고 안내한다.
- 호가·최근 체결: 토스 `/orderbook`, `/trades`.

## 알림 (사용자 결정 2026-10-21)

텔레그램 봇과 화면으로 알린다.

- 사용자가 BotFather로 개인 봇을 만들고, 봇 토큰과 본인 chat ID를 토스 키와 같은 방식(숨김 입력 → Secret Manager)으로 저장한다. 서비스와 작업에는 비밀 참조로만 연결한다.
- 서버는 저장된 chat ID 하나에만 보낸다. 받는 쪽 주소를 요청 입력으로 받지 않는다.
- (제안) 이번 단계는 보내기만 한다. 텔레그램으로 명령을 받는 기능(예: 긴급 정지)은 넣지 않는다. 받으려면 webhook 인증 설계가 필요하다.
- 알릴 일: 체결(가상·실전 구분), 알고리즘 자동 정지, 주문 거부·데이터 오류·작업 실패, 아침 브리핑, 위험을 늘리는 설정 변경(실전 켜기, 운용 금액 한도 상향, 긴급 정지 해제).
- 메시지 내용은 최소로 한다: 종목, 방향, 상태, 알고리즘 이름, 화면 링크. 계좌 식별값, 토큰, 제공자 오류 원문은 넣지 않는다. 금액과 수량은 화면에서 본다.
- 텔레그램 전송이 실패해도 매매 판단은 막지 않는다. 대신 실패를 화면 알림 목록에 남긴다.
- 화면에서는 알고리즘 화면에 최근 알림 목록을 보여 준다.

## 4. 알고리즘 자동 매매 (사용자 결정)

위치: 내 자산 페이지 안의 "알고리즘" 화면.

**실행 주기**(사용자 결정 2026-10-21): 시장별로 하루 한 번, 정규장 개장 직후에 판단한다. 국내는 KRX 개장 직후, 미국은 미국 정규장 개장 직후(KST 22:30 서머타임 / 23:30)다. Cloud Scheduler가 Cloud Run Job을 실행한다.

- 휴장일, 단축 거래일, 서머타임 전환은 토스 장 운영 캘린더 API(Market Info 그룹)로 판단한다. 휴장이면 판단하지 않는다.
- 입력: 직전 거래일까지의 일봉, 공시 기준 재무, 최근 수급(국내만, 데이터별 반영 시점이 장중 잠정치~T+1이다), 판단 시점의 현재가.
- 모의 운용과 실전 운용은 같은 작업, 같은 시각에 돈다. 결과만 가상 기록과 실제 주문으로 나뉜다.
- (제안) 주문은 지정가 `LIMIT` + `DAY`로 낸다. 토스 명세상 `DAY`의 미체결분은 정규장 종료 때 자동 취소되므로 다음 판단 때 미체결 주문이 남지 않는다. 그래도 판단 전에 미체결 주문 목록(`GET /orders?status=OPEN`)을 확인한다.

**대상 종목**(사용자 결정 2026-10-21): 알고리즘마다 대상 종목 목록을 직접 지정한다. 과거 시뮬레이션, 모의 운용, 실전이 같은 목록을 쓴다. 관심종목이나 보유 종목을 바꿔도 대상은 바뀌지 않는다. 목록을 바꾸면 그 시점을 기록하고, 이후 성과를 이전 성과와 구분해 보여 준다.

- (제안) 실전으로 켠 알고리즘 두 개가 같은 종목을 동시에 대상으로 가질 수 없다. 모의 운용끼리는 겹쳐도 된다.

**판단 구조**: 네 가지 신호를 종합해 매수·매도·보유를 정한다.

- 가치: PER·PBR 등으로 저평가·고평가 판단
- 시장 상황: 뉴스·금리 등 거시 지표
- 수급: 최근 외국인·기관 순매수로 시점 판단
- 차트: 추세, 과매수·과매도 등 기술적 신호

종합 방식은 두 가지다. 수식형은 신호별 점수 × 가중치의 합이 기준값을 넘으면 매수하는 방식이고 파라미터를 조정할 수 있다. AI형은 같은 신호 요약을 AI에 주고 판단과 근거를 받는다. 두 방식은 같은 입력과 같은 출력 형식을 써서 나란히 비교할 수 있게 한다.

**등록**(제안): 코드를 직접 쓰지 않고, 쓸 신호를 고르고 가중치·기준값을 조정하는 템플릿형으로 만든다. 모멘텀, 평균회귀, 듀얼 모멘텀 등 알려진 이론을 미리 만든 전략으로 제공한다.

**검증 흐름** (모든 알고리즘 공통)

1. 과거 시뮬레이션: 수식형만 대상이다. AI형은 제외한다. AI 모델이 과거 결과를 이미 알고 있어 수익률이 부풀려지고, 재현성과 비용 문제도 있기 때문이다. 각 시점에 실제로 공개되어 있던 데이터만 쓴다.
   - (제안) 과거 데이터를 시점 기준으로 확보할 수 있는 신호는 차트(토스 캔들)와 가치(DART·SEC 재무, 공시일 기준)뿐이다. 수급은 토스가 최근 기간만 주고, 뉴스는 수집을 시작한 날 이후만 있다. 그래서 과거 시뮬레이션은 차트·가치 신호만으로 돌리고 결과에 "수급·뉴스 신호 제외"를 표시한다. 수급·뉴스·시장 지표는 구현 시작 시점부터 매일 저장해, 쌓인 기간만큼 전체 신호 시뮬레이션이 가능해지게 한다. 크롤링 금지 규칙 때문에 유료 공급자 없이 과거 수급·뉴스를 채울 방법은 없다.
   - 토스 캔들의 과거 제공 범위(요청당 200봉, `before` 페이지 조회)는 구현 전에 실제로 확인한다.
2. 모의 운용: 오늘부터 실제 시세로 매일 판단하고 가상 매매 기록을 쌓는다. AI형은 여기서 시작한다.
3. 실전 운용: 운용 금액을 정해 자동 체결을 켠다.
   - 실전 전환 기준(사용자 결정 2026-10-21): 시스템이 정한 최소 기간이나 성과 조건은 없다. 사용자가 시뮬레이션·모의 운용 성과를 보고 매번 판단해 켠다. 실전 켜기 화면에는 모의 운용 기간, 가상 왕복 횟수, 비용 차감 후 수익, 최대 낙폭을 함께 보여 준다.
   - 기준이 없어도 아래 "예상 이익 > 왕복 비용" 규칙은 실전에서 그대로 적용된다. 그래서 기록이 부족한 알고리즘은 실전으로 켜도 주문이 나가지 않을 수 있다. 화면에서 "기록 부족으로 주문 보류"라고 이유를 보여 준다.

**결과 지표**: 총수익, 수수료·환전·세금 비용, 비용 차감 후 수익, 최대 낙폭, 변동성.

**주문**: 조건이 맞으면 자동 체결한다. 토스 `POST /api/v1/orders`(국내·미국)를 쓰고, 주문 전 `/buying-power`, `/sellable-quantity`로 확인한다.

- 토스 명세 v1.2.24 확인 사항(2026-10-21): 주문 요청의 `clientOrderId`는 10분 동안 유효한 멱등 키다. 재시도 때 같은 값을 써서 중복 주문을 막는다. `timeInForce`는 `DAY`(기본), `CLS`(미국 지정가 장마감), `OPG`(국내 시가단일가)를 지원한다. 1억 원 이상 주문은 `confirmHighValueOrder: true`가 필요한데, 이 시스템은 이 값을 켜지 않는다. 주문 API는 `ORDER`, 주문 전 조회는 `ORDER_INFO` 호출 한도 그룹이다.

**주문 권한 확인**(사용자 결정 2026-10-21): 토스 OAuth에는 scope가 없고(`scopes: {}`), `POST /orders`에는 403 응답이 정의되어 있지 않다. 그래서 키 단위로 주문 권한이 구분되는지는 명세로 확인할 수 없다. 실제 주문 없이 아래 순서로 확인한다.

1. 구현 때 고정 출구 IP를 쓰는 일회성 작업으로 `GET /buying-power`(KRW·USD), `/commissions`, `GET /orders?status=OPEN`을 조회한다. 계좌 단위 주문 계열 API에 접근할 수 있는지 확인한다. 응답 원문과 계좌 식별값은 출력하지 않는다.
2. 사용자가 토스증권 WTS 설정 > Open API 화면에서 주문 관련 설정을 확인한다.
3. 실전을 처음 켠 뒤 나간 첫 주문이 권한 문제로 거부되면, 해당 알고리즘을 정지하고 텔레그램으로 알린다.

명세상 403 "권한 부족"은 종목 목록, 매수 유의사항, 국내 수급(투자자 동향·프로그램매매·공매도·신용·대차) 조회에 정의되어 있다. 이 API들도 구현 전에 실제 호출로 확인한다.

**비용 반영**

- 매매 수수료율: 토스 `/api/v1/commissions` 값을 쓴다.
- 환전(사용자 결정 2026-10-21): 토스 API에는 환전을 실행하는 엔드포인트가 없다. 미국 종목 알고리즘은 **계좌에 있는 달러만** 쓴다. 운용 금액 한도는 달러로 정하고, 주문 전에 `GET /buying-power?currency=USD`의 현금 매수 가능 금액을 확인한다. 달러가 부족하면 주문하지 않고 알린다. 환전은 사용자가 직접 한다.
  - 달러로 사고 달러로 팔기 때문에 환전 비용은 왕복 비용에 넣지 않는다. 미국 알고리즘의 성과는 달러 기준으로 보여 주고, 원화 환산은 `/exchange-rate`의 `midRate`(매매기준율)로 계산해 참고로 함께 표시한다. 원화 환산 손익에는 환율 변동이 섞인다는 점도 표시한다.
  - 참고: `/exchange-rate`의 `basisPoint`는 매매기준율 대비 스프레드다. 실제 주문 환율과 다를 수 있다. 사용자가 직접 환전한 비용을 추정해 보여 줄 때만 쓴다.
- 세금: 증권거래세, 해외주식 양도소득세는 API에 없고 세율이 바뀔 수 있으므로 설정값으로 둔다.
- 알고리즘을 만들 때 시뮬레이션 결과에 비용을 따로 보여 주고, 실전에서는 예상 이익이 왕복 비용보다 클 때만 주문한다.
- (제안) 수식형의 "예상 이익"은 같은 알고리즘이 과거 시뮬레이션·모의 운용에서 같은 점수 구간의 신호를 냈을 때의 평균 수익률로 계산한다. 기록이 충분하지 않으면 주문하지 않는다. AI형은 판단과 함께 예상 수익률 범위를 출력하게 한다.

**안전장치** (기본값은 사용자 결정 2026-10-21 "기본안". 설정에서 바꿀 수 있고 변경 이력을 남긴다)

1. 알고리즘별 운용 금액 한도: 기본값이 없다. 실전을 켤 때 반드시 입력한다. 국내는 원화, 미국은 달러로 정한다.
2. 하루 최대 주문 횟수: 알고리즘당 3건, 전체 10건. 최소 보유 기간: 5거래일. 이 기간 안에는 매도 신호가 나와도 매도하지 않는다.
3. 중복 주문 방지: 미체결 주문이 있으면 새 주문 금지. 재시도는 같은 `clientOrderId`로 한다.
4. 누적 손실(실현 + 평가)이 운용 금액의 -20%에 닿으면 해당 알고리즘을 자동 정지하고 알린다(사용자 결정 2026-10-21, 기본안 -10%에서 변경).
5. 모든 자동 매매를 끄는 긴급 정지 버튼
6. 데이터 신선도: 직전 거래일 일봉이 없거나, 판단 시점 1분 안에 받은 현재가가 없으면 주문하지 않는다. 재무 데이터가 비어 있으면 가치 신호를 쓰는 알고리즘은 주문하지 않는다.
7. 알고리즘은 자기가 산 수량만 매도(직접 보유분 보호)
8. 기본 지정가 주문. 최근 20거래일 평균 거래대금이 국내 10억 원, 미국 500만 달러보다 적은 종목은 제외한다.
9. 매수 유의사항(투자경고·거래정지 등) 종목 제외
10. 1억 원 이상 주문은 내지 않는다(`confirmHighValueOrder`를 켜지 않음).

**설정 변경 인증**(사용자 결정 2026-10-21): 실전 켜기, 운용 금액 한도 상향, 긴급 정지 해제에 추가 인증을 두지 않는다. 로그인 세션만 있으면 된다. 대신 이 변경이 일어날 때마다 텔레그램으로 바로 알린다. 본인이 한 변경이 아니면 사용자가 긴급 정지로 막는다. 위험을 줄이는 동작(긴급 정지, 알고리즘 끄기, 한도 낮추기)도 추가 인증 없이 바로 된다.

- 남는 위험: 세션(8시간)을 탈취당하면 탈취한 사람이 실전을 켜고 한도를 올릴 수 있다. 알림을 받고 긴급 정지하기 전에 다음 판단 시각이 오면 실제 주문이 나갈 수 있다. 사용자가 이 위험을 받아들였다. MFA 등은 필요해지면 별도 작업으로 넣는다.

## 5. AI 모델 (사용자 결정)

아침 브리핑, 번역, AI 해설, 알고리즘 판단을 모두 `gemini-3.8-flash` 하나로 통일한다. 2026-10-20에 개인 프로젝트 Vertex AI global에서 공개 예시 문장 1회 실호출을 확인했다. `gemini-3.8-flash-lite`는 Vertex 목록에 없다.

- 이 모델은 생각(thinking) 토큰을 출력 토큰으로 소비한다. 시험 호출에서 출력 한도 200 중 188이 생각에 쓰여 답이 잘렸다. 작업별로 생각 토큰 한도와 출력 한도를 따로 정한다.
- 현재 하루 25회 공용 한도([ai-provider.md](../implementation/ai-provider.md))는 기능별 한도로 나눈다.
- 공식 가격표로 월 예상 비용을 계산해 이 문서에 추가한 뒤 사용자 승인을 받는다.

5. 종목 분석 탭: 지표·툴팁 → 재무·가치 지표 → 수급·업종·호가 → 이벤트 수직선 → 내 매매 표시.
6. 텔레그램 알림 발송 모듈. 아침 캘린더 갱신 작업과 Cloud Scheduler(Terraform).
7. 알고리즘: 수식형과 과거 시뮬레이션 → 모의 운용(AI형 포함) → 주문 권한 읽기 확인 작업 → 안전장치와 실전 자동 체결.
8. 도메인: 당분간 Cloud Run 기본 주소(run.app)를 쓴다. 이 단계에서 연결 방식(부하분산기, Firebase Hosting 등)과 비용을 비교해 사용자와 정한다. 도메인 이름은 공개 저장소가 아니라 `.local`에만 기록한다.

함께 처리할 운영 과제:

- `scripts/gcp.mjs`와 `scripts/connect-toss.mjs`를 Windows에서도 동작하게 고친다. 지금은 `execFileSync('gcloud')`가 `gcloud.cmd`를 찾지 못한다. 셸 문자열 실행은 인자 주입 위험이 있으므로 쓰지 않는다. gcloud 실행 경로를 찾아 실행하는 방식으로 고치고, 비밀이 프로세스 인자나 로그에 나오지 않는다는 기존 보장을 유지한다.
- `.gitattributes`에 `* text=auto eol=lf`를 추가해 Windows에서도 Prettier 검사가 통과하게 한다.

- Terraform 상태 파일을 로컬에서 접근 제한된 원격 저장소(GCS backend)로 옮긴다. 지금은 한 컴퓨터에만 있어 분실 시 인프라 관리가 끊긴다.
- `connect-toss.mjs` 사전 확인이 배포 이미지에 `toss-setup.ts`가 있는지 검사하지 않는다.
- 2026-10-20 첫 사전 확인에서 gcloud 응답이 60초 넘게 지연되어 실패한 적이 있다. 재실행 시 정상이었고 원인은 확인하지 못했다.
