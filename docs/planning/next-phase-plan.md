기준: 2026-10-21 KST. 상태: **승인, 실행 중**(2026-10-21 사용자 승인). 감독(Claude Opus)이 지시·검사·리뷰하고, 단계별 구현은 Claude Sonnet 에이전트가 각자의 git worktree 브랜치에서 맡는다. 근거는 확정 설계 [next-phase-design.md](next-phase-design.md)다. 설계와 이 계획이 다르면 설계가 우선하고, 다른 점을 발견하면 설계를 먼저 고친다. 단계가 끝날 때마다 이 문서의 진행 표와 [상태 SOT](../implementation/status.md)를 갱신한다.

## 공통 규칙

모든 단계에 적용한다. [AGENTS.md](../../AGENTS.md)가 우선한다.

- 한 단계 = 한 PR. PR은 `main`의 필수 CI(앱 검증·인프라 검증·컨테이너 스모크)를 통과해야 병합되고, 병합된 SHA만 자동 배포된다.
- PR마다 기능 테스트, `npm run check`, 해당하면 `npm run test:e2e`, 기능 문서 갱신을 함께 한다. UI 변경은 데스크톱·모바일 실제 렌더링을 확인하고 [evidence.md](../testing/evidence.md)에 기록한다.
- 외부 API 계약: 새 엔드포인트를 쓰기 전에 공식 명세를 다시 확인하고, 기능 문서에 명세 버전과 확인 날짜를 적는다. 명세에 없는 필드는 만들지 않는다. 응답은 기존 `toss.ts`처럼 형식 검사 후 정규화하고, 형식이 다르면 `PROVIDER_SCHEMA_INVALID`로 실패한다.
- 새 개인 API는 모두 로그인과 **소유자 검사**를 서버에서 한다. 숨긴 UI는 보안 경계가 아니다.
- 새 키는 Secret Manager에만 저장하고 서비스·작업에는 비밀 참조로만 연결한다. 키 값, 계좌 식별값, 제공자 오류 원문은 로그·응답·채팅에 내보내지 않는다.
- 테스트는 외부 통신 없이 주입한 transport와 `tests/fixtures`의 합성 응답으로 돌린다. 합성 fixture를 실데이터 검증이라고 쓰지 않는다. 실제 호출 확인은 따로 기록한다.
- 인증·인프라·데이터 연동·주문 변경 PR은 [collaboration.md](../agents/collaboration.md)에 따라 별도 보안 검토를 받는다(가능하면 Claude Sonnet 읽기 전용 검토, 정제된 소스 사본만 제공).
- 클라우드 리소스 생성·변경은 지정 개인 계정과 프로젝트를 명시한 `plan`을 확인한 뒤 적용한다. `plan`에 의도하지 않은 교체가 있으면 적용하지 않는다.

## 전체 순서

```
0 기반 정비 ─┬─ 1 규칙 문서 변경 ─── 3 데모 제거·소유자 전용 ─┬─ 4 일일 데이터 적재 ─── 6 아침 갱신 ─┐
             └─ 2 키 준비(사용자) ──────────────────────────┤                                    ├─ 7 알고리즘 ─ 8 도메인
                                                             └─ 5 종목 분석 탭 ────────────────────┘
```

- 0과 1은 서로 독립이라 함께 진행할 수 있다. 2는 사용자 작업이며 0과 동시에 시작한다.
- 4(일일 데이터 적재)는 일찍 시작할수록 좋다. 수급·뉴스·시장 지표는 쌓인 기간만큼만 전체 신호 시뮬레이션에 쓸 수 있기 때문이다.
- 5(종목 분석)와 4·6(작업 계열)은 파일이 겹치지 않으므로 병렬로 진행할 수 있다.
- 7(알고리즘)은 3·4·5b(재무)·6a(알림)가 끝나야 시작한다.

## 0. 기반 정비

목적: 어느 컴퓨터에서든 검증과 운영 명령이 같은 결과를 내게 한다. 기능 코드는 바꾸지 않는다.

- (완료 2026-10-21) `.gitattributes`에 `* text=auto eol=lf`를 추가하고 저장소를 다시 정규화했다. PNG 등 이진 파일은 `binary`로 둔다.
- `scripts/gcp.mjs`, `scripts/connect-toss.mjs`, `scripts/toss-secrets.py`의 gcloud 실행을 Windows에서도 되게 한다.
  - 공통 해석 함수를 둔다. macOS/Linux는 지금처럼 `gcloud`를 바로 실행한다. Windows는 PATH에서 `gcloud.cmd`를 찾아 SDK 루트를 구한 뒤, 번들 Python(또는 `CLOUDSDK_PYTHON`)으로 `lib/gcloud.py`를 셸 없이 실행한다.
  - 셸 문자열 실행(`shell: true`, `cmd /c`)은 인자 주입 위험이 있어 쓰지 않는다. 비밀은 계속 stdin으로만 넘긴다.
  - 해석에 실패하면 원인과 WSL 사용 안내만 출력하고 중단한다.
- `connect-toss.mjs` 사전 확인에 "배포 이미지에 `toss-setup.ts` 진입점이 있는지" 검사를 추가한다(설계의 운영 과제).
- Terraform state를 GCS backend로 옮긴다.
  - 개인 프로젝트에 버전 관리와 균일 버킷 접근을 켠 비공개 버킷을 만든다. 공개 접근을 막고 접근 권한은 사용자 계정만 둔다.
  - `terraform init -migrate-state` 후 `plan`이 "No changes"인지 확인한다. 로컬 state 파일은 확인 뒤에도 바로 지우지 않고 사용자가 안전한 곳에 백업한다.
  - **사용자 확인 필요**: 버킷 생성은 클라우드 리소스 생성이므로 `plan` 결과를 보여 드리고 승인을 받은 뒤 적용한다.
- 문서: [next-phase-design.md](next-phase-design.md)의 Windows 참고 갱신, [deployment.md](../operations/deployment.md)의 state·backend 절 갱신.
- 테스트: `tests/connect-toss.test.ts`·`tests/test_toss_secrets.py`에 실행 경로 해석 단위 테스트(플랫폼·PATH 주입) 추가. Windows와 Linux 양쪽에서 `npm run check` 통과.
- 완료 기준: Windows에서 `node scripts/gcp.mjs doctor`·`plan`, `node scripts/connect-toss.mjs` 사전 확인이 통과하고, `plan`이 GCS backend로 "No changes"다.

## 2. 외부 키·텔레그램 봇 준비

사용자 작업이며 0단계와 동시에 시작한다.

- 사용자: DART, FRED, ECOS 키를 발급한다. BotFather로 개인 봇을 만들고 봇과 대화를 시작해 chat ID를 확인한다.
- 구현: `scripts/toss-secrets.py`를 고정 이름 목록을 받는 범용 입력 도구로 넓히거나 같은 방식의 `scripts/provider-secrets.py`를 만든다. 숨김 입력 → gcloud stdin → Secret Manager. 비밀 이름은 코드에 고정하고 요청 입력으로 받지 않는다.
  - 이름(제안): `investing-dart-api-key`, `investing-fred-api-key`, `investing-ecos-api-key`, `investing-telegram-bot-token`, `investing-telegram-chat-id`.
- Terraform: 위 비밀 리소스와, 이를 읽을 서비스 계정별 `secretAccessor`를 비밀 단위로 추가한다. 프로젝트 단위 권한은 주지 않는다.
- SEC EDGAR는 키가 없지만 User-Agent에 연락처가 필요하다. 연락처는 공개 저장소에 쓰지 않고 비밀이 아닌 환경 설정(배포 변수)으로 둔다.
- 완료 기준: 비밀 버전이 모두 있고, 각 서비스 계정이 필요한 비밀만 읽을 수 있다(`plan`으로 확인).

## 3. 데모 제거·소유자 전용

설계 [1. 데모 제거](next-phase-design.md#1-데모-제거-사용자-결정).

서버

- 소유자 검사를 공통 미들웨어(`requireOwner`)로 뺀다. 지금은 `TossClient` 안에서만 `ownerUserId`를 비교한다. 앱 옵션으로 소유자 ID를 받고, 이번 단계의 모든 새 API에 적용한다. 소유자가 아니면 403 `OWNER_REQUIRED`, 토스 미설정이면 503 `TOSS_INTEGRATION_UNAVAILABLE`.
- 새 API: `GET /api/market/prices?symbols=`(토스 `/prices`), `GET /api/market/indicators`(토스 `/market-indicators/prices` + `/exchange-rate`). 기존 30초 캐시와 동시 요청 합치기를 그대로 쓴다.

화면

- `src/lib/market.ts`의 `demoPrices`, `events`를 지운다. 지표 계산 함수는 남긴다.
- 캘린더·차트·AI 인사이트의 데모/실제 전환 버튼, 내 자산 예시 보유와 DEMO 표시, 상단 "예시 시세" 띠, 둘러보기 모드를 없앤다. 로그인 전에는 로그인 화면만 보인다.
- 상단 띠를 실제 지수·환율로 바꾼다.
- 공통 상태 컴포넌트: 토스 미연결 / 데이터 없음 / 일시 오류(다시 시도) / 소유자 전용 안내. 데이터를 못 받으면 데모로 대체하지 않는다.
- `src/lib/strategy.ts`의 새 전략 입력 초기값은 그대로 둔다.

테스트

- E2E(`tests/app.spec.ts`, `tests/ui-regressions.spec.ts`, `tests/providers.spec.ts`, `tests/recommendations-live.spec.ts`)를 `page.route` 가짜 응답과 `tests/fixtures`로 바꾼다. 가짜 데이터는 테스트 코드에만 둔다.
- 서버 통합 테스트: 비로그인 401, 일반 회원 403, 소유자 200, 토스 미설정 503.
- 화면 테스트: 세 가지 오류 상태와 소유자 전용 안내가 각각 보이는지.

완료 기준: 저장소 `src/`에 데모 시세·일정이 남아 있지 않다(검색으로 확인). 운영에서 소유자 로그인 시 실제 지수·보유가 보이고, 다른 계정은 안내만 본다. 보안 검토 대상이다.

## 4. 일일 데이터 적재 작업

목적: 과거 시뮬레이션에 필요한 시점 기준 데이터를 지금부터 쌓는다.

- 작업 실행 기반(이후 6b·7c도 재사용): `src/jobs/` 진입점, Cloud Run Job(같은 이미지, `node --import tsx src/jobs/<name>.ts`), Cloud Scheduler(Terraform). 작업별로 최소 권한 서비스 계정을 둔다. 고정 출구 IP를 쓰도록 기존 VPC를 쓴다.
- 작업 `investing-daily-snapshot`: 국내 장 마감 후와 미국 장 마감 후에 실행한다(시각은 장 운영 캘린더로 판단, 휴장이면 건너뜀).
  - 저장: 관심 범위 종목의 일봉, 국내 수급(투자자 동향·프로그램·공매도·신용), 시장 지표(코스피·코스닥·국채), 공식 뉴스 RSS 수집 결과. 각 레코드에 `observedAt`(받은 시각)과 원천 기준일을 함께 저장한다.
  - 대상 종목: 보유 종목 + 알고리즘 대상 종목(7a 이후) + 소유자가 지정한 적재 목록.
- Firestore 컬렉션(제안): `marketSnapshots/{market}_{date}_{symbol}`. 서버 전용, 클라이언트 접근 차단 규칙 유지.
- 테스트: 작업 단위 테스트(휴장 건너뜀, 부분 실패 시 이미 받은 데이터 보존, 같은 날 재실행 시 중복 없음).
- 완료 기준: 운영에서 이틀 연속 자동 실행되고 데이터가 쌓인다. 실패는 작업 로그의 정제된 오류 코드로 확인한다.

## 5. 종목 분석 탭

설계 [2. 종목 분석 탭](next-phase-design.md#2-종목-분석-탭-사용자-결정). 탭 이름 "종목 분석", 시안 A 배치. 하위 PR로 나눈다.

- **5a 지표·요약**: 탭 이름 변경, 종목 검색(토스 `/stocks`), 요약(현재가·등락률, 유의사항·상하한가 배지). 지표 추가(일목균형표, VWAP, 스토캐스틱, ATR, OBV, 파라볼릭 SAR, ADX, CCI, 켈트너 채널, 피보나치 되돌림)와 지표마다 ⓘ 설명. 계산은 `src/lib/`의 순수 함수로 두고, 경계값과 데이터 부족 구간 테스트를 `tests/market.test.ts` 계열에 추가한다. 긴 기간은 `before` 페이지 조회로 받는다.
- **5b 재무·가치 지표**: DART 어댑터(국내 재무·공시), SEC EDGAR 어댑터(companyfacts·공시). 회사 식별 매핑(DART 고유번호, SEC CIK)은 서버에 캐시한다. PER·PBR·ROE·EPS를 직접 계산하고 출처·공시일·계산 시점을 함께 돌려준다. 업종 평균은 토스 `/sectors` 구성 종목으로 계산한다. 이 계산 함수는 7b 시뮬레이션이 공시일 기준으로 재사용한다.
- **5c 수급·호가**: 투자자 동향, 공매도·신용·프로그램매매(국내만, 미국은 "제공하지 않음" 안내), 호가·최근 체결. 403이면 "토스 권한 없음"으로 따로 표시한다.
- **5d 이벤트 수직선**: 캘린더 이벤트, FRED·ECOS 발표, DART 공시, SEC 공시를 차트 날짜에 점선과 이름표로 그린다. 중요도·종류·시장 필터. 미국 실적은 발표 후 날짜만 그린다.
- **5e 비교·내 매매**: 코스피·코스닥(토스 시장 지표 캔들), S&P 500(추종 ETF), 원/달러(ECOS)를 기준 100으로 정규화해 겹친다. 평균 매수가 가로선. 알고리즘 체결 ▲▼ 마커는 7c 이후 연결한다.
- 공통 테스트: 어댑터 계약 테스트(합성 fixture), 계산 단위 테스트, E2E(가짜 응답), 데스크톱·모바일 렌더링 확인.
- 완료 기준: 국내·미국 대표 종목 각 1개를 운영에서 실제로 열어 각 영역이 실데이터 또는 명확한 "제공 안 함/권한 없음" 상태로 보인다.

## 6. 알림과 아침 캘린더 갱신

- **6a 텔레그램 알림**: `src/server/notify.ts`. 저장된 chat ID 하나에만 `sendMessage`로 보낸다(Telegram Bot API, 공식 문서 확인 후). 받는 주소와 봇 토큰을 요청 입력으로 받지 않는다. 메시지는 설계의 최소 내용만 담는다. 보낸 알림과 실패를 Firestore `notifications`에 남기고 화면 알림 목록 API(`GET /api/notifications`, 소유자 전용)를 만든다. 전송 실패가 호출한 기능을 실패시키지 않는다. 테스트: 메시지에 계좌 식별값·토큰·긴 숫자가 들어가지 않는지, 실패 시 기록되는지.
- **6b 아침 캘린더 갱신**: 작업 `investing-morning`, 매일 07:00 KST(제안).
  1. 지난 이벤트에 FRED·ECOS 실제 발표값·이전값을 붙인다.
  2. 다가오는 이벤트를 공식 API로 찾아 추가한다(같은 ID로 upsert, 중복 없음).
  3. AI가 결과·시장 영향 요약(두세 문장)과 미국 이벤트 한국어 번역을 만든다. 원문은 출처 링크로 남긴다.
  4. 브리핑을 화면과 텔레그램으로 보낸다.
  - AI: `gemini-3.8-flash`로 바꾸고, 작업별 생각 토큰·출력 한도와 기능별 일일 한도를 둔다. 기존 하루 25회 공용 한도를 기능별로 나눈다.
  - **사용자 확인 필요**: 공식 가격표로 월 예상 AI 비용을 계산해 설계 문서에 추가하고, 승인을 받은 뒤 운영에서 AI 단계를 켠다. 승인 전에는 AI 단계 없이 1·2·4만 돈다.
- 완료 기준: 운영에서 아침 작업이 자동 실행되고 캘린더에 실제 값과 새 이벤트가 생기며 텔레그램으로 브리핑이 온다.

## 7. 알고리즘

설계 [4. 알고리즘 자동 매매](next-phase-design.md#4-알고리즘-자동-매매-사용자-결정). 실제 돈이 걸리는 단계라 하위 PR을 작게 나누고 7d·7e는 보안 검토를 받는다.

- **7a 모델·화면**: 내 자산 안 "알고리즘" 화면. Firestore `algorithms/{id}`(소유자 전용): 이름, 방식(수식형·AI형), 템플릿(모멘텀·평균회귀·듀얼 모멘텀), 신호 선택·가중치·기준값, 대상 종목 목록(변경 이력 포함), 모드(시뮬레이션·모의·실전), 운용 금액 한도(통화별). 설정 변경 이력을 `algorithmEvents`에 남긴다. 실전 알고리즘끼리 대상 종목이 겹치면 저장을 거부한다.
- **7b 수식형과 과거 시뮬레이션**: `src/lib/algo/`에 순수 함수로 신호 점수, 종합, 체결 가정, 비용(토스 수수료율 + 세금 설정값), 결과 지표(총수익, 비용, 비용 차감 후 수익, 최대 낙폭, 변동성)를 만든다. 각 시점에 공개되어 있던 데이터만 쓴다: 캔들은 해당 날짜까지, 재무는 공시일 기준(5b 재사용). 결과에 "수급·뉴스 신호 제외"를 표시한다. 점수 구간별 평균 수익률을 저장해 "예상 이익"에 쓴다. 테스트: 미래 데이터 누수가 없는지(시점 이후 값을 바꿔도 결과가 같은지), 비용 계산, 최소 보유 기간 반영.
- **7c 모의 운용 작업**: 작업 `investing-algo-kr`(KRX 개장 직후), `investing-algo-us`(미국 정규장 개장 직후). 미국은 서머타임 때문에 KST 22:3x와 23:3x 두 번 스케줄하고, 작업이 장 운영 캘린더로 "지금이 개장 직후인지" 판단해 한 번만 실행한다. 판단 결과와 가상 체결을 `algorithmRuns`, `paperTrades`에 저장한다. AI형은 별도 판단 계약(입력: 신호 요약, 출력: 판단·근거·예상 수익률 범위, 형식 검사)으로 호출하고 기능별 한도를 둔다. 체결은 텔레그램으로 알린다(가상 표시).
- **7d 주문 기반**: 먼저 고정 IP 일회성 작업으로 주문 계열 읽기 접근을 확인한다(설계 주문 권한 확인 1). 그다음 토스 주문 클라이언트(`POST /orders`, `GET /orders`, `GET /orders/{id}`, 취소)를 만든다. 모든 주문에 `clientOrderId`를 붙이고 재시도는 같은 값으로만 한다. 안전장치 10개를 주문 직전의 한 함수(`preTradeCheck`)에 모아 하나라도 걸리면 주문하지 않고 이유를 기록한다. 테스트는 가짜 토스 서버로만 하며 실제 주문을 내는 테스트는 없다. 안전장치마다 걸리는 경우와 통과하는 경우를 각각 테스트한다.
- **7e 긴급 정지·자동 정지·설정 알림**: 전체 긴급 정지 플래그(Firestore, 작업이 주문 직전마다 다시 읽음), 누적 손실 -20% 자동 정지, 위험을 늘리는 설정 변경(실전 켜기·한도 상향·긴급 정지 해제)마다 텔레그램 즉시 알림. 추가 인증은 두지 않는다(사용자 결정). 위험을 줄이는 동작은 즉시 반영한다.
- **7f 실전 켜기**: 실전 켜기 화면(모의 성과 요약, 운용 금액 입력 필수, "기록 부족으로 주문 보류" 안내), 첫 실전 주문 거부 감시(거부되면 알고리즘 정지 + 알림), 체결 마커를 종목 분석 차트(5e)에 연결. 실전 주문 기록은 `liveOrders`에 남긴다.
  - **사용자 작업**: WTS 설정 > Open API 화면에서 주문 관련 설정 확인(설계 주문 권한 확인 2). 첫 실전은 사용자가 작은 운용 금액으로 직접 켠다.
- 완료 기준: 7c는 운영에서 영업일마다 모의 판단이 쌓인다. 7f는 사용자가 실전을 켠 뒤 첫 주문의 결과(체결·거부)가 기록되고 텔레그램으로 온다. 실제 체결 여부와 무관하게 결과를 그대로 기록한다.

## 8. 도메인

설계대로 당분간 Cloud Run 기본 주소를 쓴다. 마지막에 연결 방식(전역 부하분산기, Firebase Hosting 연결 등)의 비용과 제약을 공식 문서로 비교해 사용자와 정한다. 도메인 이름은 `.local`에만 기록하고, `APP_ORIGIN`을 함께 바꾼다.
