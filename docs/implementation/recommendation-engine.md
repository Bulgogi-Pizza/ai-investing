# 실데이터 기반 규칙 추천

구현: src/server/recommendations.ts, app.ts. 테스트: tests/recommendations.test.ts. GET /api/recommendations?period=daily|weekly|monthly&symbol=005930. 기본 daily/005930, 인증 필수. 토스 미설정503, 저장된 계정 전략 없음409 STRATEGY_REQUIRED, 토스 소유 계정 불일치403. 생성 전에 토스 portfolio의 소유자 검사를 통과해야 한다. 실제 데이터 오류 시 데모로 대체하지 않는다.

engine=rules-v1, dataMode=live는 공급자 데이터로 계산하는 결정적 규칙이며 생성형AI나 전문가 판단을 뜻하지 않는다. 실제 토스 보유 주식과 수정주가 일봉90개를 조회하고 최소21개로 SMA20, 최근14개 변화 단순합산 RSI14, 1/5/20거래일 수익률을 계산한다. 최종 일봉이 조회시각보다10일 이상 오래되거나 미래1일을 초과하면503 STALE_MARKET_DATA다. 중복·역순 시각, 비정상 가격, 통화 혼합은503이다.

저장된 위험성향 low/medium/high를 점검 임계2/4/6%에 대응한다. 해당 기간 수익률이 음의 임계 이하이거나 RSI>=70, 등록된 중요도3 일정이 있으면 review-risk. 그렇지 않고 양의 임계 이상·SMA20 이상·RSI<70이면 review-opportunity. 나머지는 hold-plan이다. 임계는 손실 한도나 예측 가격이 아니며 주문을 실행하지 않는다. 목표 비중·벤치마크·선호는 전략 스냅샷으로 보여 주지만 외부 벤치마크 수익률과 비용을 계산하거나 전체 포트폴리오 리밸런싱을 최적화하지 않는다.

기간별 향후 일정은 KST 기준 오늘부터1/7/30달력일까지 조회하며 지난 시각은 제외한다. 공유 cleanEvent 검증기로 저장 레코드를 먼저 검증·허용필드 투영한다. 6자리 숫자 종목은 한국, 나머지는 미국으로 분류하여 같은 시장·글로벌 일정이나 assets에 종목이 명시된 일정만 참조한다. 영숫자 혼합 한국 종목은 이 단순 분류의 한계가 있으므로 명시적인 종목 태그가 필요하다. relevanceRule과 excludedCount(검증 실패 또는 관련 시장에서 제외된 수)를 근거에 반환한다. 시장 일치만으로 거시 일정의 직접적인 종목 영향을 확정하지 않는다. 계정 내 관리자가 등록한 출처 포함 일정만 참조한다. 전체 뉴스·공시·모든 시장 이벤트가 연결되었다고 표시하지 않는다. 일정이0개여도 시장 입력이 있으면 계산하되 커버리지 경고를 포함한다. 저장소 최대2001개 조회, 최대50개 근거 일정 반환, 나머지는 truncated로 표시한다. 비밀·authorId를 근거 응답에서 제외한다.

응답은 asOf, period, symbol, horizon, strategy, decision, metrics, evidence.market의 실제 정규화 일봉과 제공자 시각, evidence.calendar의 출처/관측시각/조회기간/커버리지 경고, scenarios, risks, stockExposureByCurrency를 포함한다. 비중은 동일 통화의 주식끼리만 계산하며 현금·채권·옵션과 환율이 없으므로 전체 자산 배분을 의미하지 않는다. 지표 산술은 표시·설명용 부동소수점이다. 수익 확률·숫자 신뢰도를 만들지 않는다.

사용자별 인스턴스당 분당3요청을 전용 제한하고 전체 API 제한도 적용한다. 공급자 조회는30초 캐시/singleflight를 재사용한다. 두 인스턴스에서는 제한이 합산될 수 있으며 엄격한 계정 전체 예산이 필요하면 분산 제한 저장소가 필요하다. 실키와 고정IP 등록 전 실서비스 데이터 연결 검증은 미완료다.

## 뉴스·모델 해설 확장

`evidence.news`는 최근1/7/30일 공개 보도자료를 예정 일정과 분리한다. 게시시각은 KST, 시장 관련성·출처·잘림·범위 한계를 함께 반환한다. 제목에서 추정한 중요도로 규칙 action을 변경하지 않는다. 세부 수집 계약은 news-provider.md를 따른다. `ai`는 선택적 Vertex 해설이며 규칙 action·metrics를 바꾸지 않는다. 모델 실패에도 원본 규칙은 유지하며 disabled/unavailable 상태를 표시한다. 정보 최소화·할당량·출력 스키마는 ai-provider.md, 실제 연결 상태는 status.md를 따른다.
